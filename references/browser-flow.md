# 官方商城浏览器流程

在操作网页登录、目录、商品、结算或恢复时读取。使用宿主浏览器能力，不依赖隐藏接口；使用 Ego 的宿主遵循其技能和后台 TaskSpace 规则，其他宿主采用对应的页面所有权和交接机制。

## 入口与页面识别

- 官方电脑商城：<https://img.client.10010.com/jifenshangchengpc/index.html>
- `#/`：账户概览、通信积分/奖励积分和商品分类。
- `#/shopList`：商品列表、筛选、分页或搜索；`我能兑换`只是候选筛选。
- `#/goodinfo?goodsId=...`：商品详情。goodsId从本轮官网实际链接或弹出页取得，不沿用历史商品ID。
- `uac.10010.com/portal/...`：官方登录；支持密码和随机密码登录，可能出现拼图。
- `#/pay`：确认订单；实测含“积分扣减验证码”“获取验证码”“立即支付”。该“支付”可能为纯积分，现金额由确认订单判断。
- `#/payOk`：支付结果；读取实际积分与实付款，随后查看该订单。
- `#/orderdetail?orderNo=...`：订单详情；核对账号、商品、积分、现金和状态。

这些是观察到的页面线索，不是固定路由契约。网站变化时以当前可见内容与官方链接为准；遇到登录或验证交接，不自行改用其他浏览器。

## 本轮实测影响决策的细节

1. **加载占位**：页面载入初期可显示未登录、积分0、通讯积分不足、补货中和空商品。等待账户标识及相应业务数据加载完成再判断；零余额也可能是真实结果，不能永远等“非0”。必要时在业务加载已结束后读取合法的0。
2. **新页面**：商品卡片、首页搜索可能开新页。优先在动作前等待popup，或接管动作回执指出的新页；不要因为旧页URL没变就重复点击。
3. **同组件旧内容**：切换`goodinfo`的goodsId时，地址改变后曾仍显示上一款商品。核对URL商品身份、可见名称和价格；只读阶段可安全刷新再等正确内容。不得把旧商品内容记入新商品证据。
4. **搜索推荐区**：搜索无匹配后可能仍显示推荐商品。只有搜索结果区域的命中才算该关键词结果，不能把推荐列表当命中；必要时用一项已知商品检验搜索功能。
5. **两种购买入口**：详情中同时存在现金购买和积分购买。只有积分入口符合本技能默认任务；详情的“可抵至0元”不代替结算页核对。
6. **验证后已有结果**：本次用户完成验证后，接回时已是`payOk`。最终提交前应先读当前页面阶段；若成功或处理中，查询这笔结果，不重复支付。
7. **订单异步完成**：本次支付成功后，订单先显示处理中，后更新已完成。已支付的处理中订单不可因仍见“去支付”等残留按钮而再次付款。

## 页面观察与交接

- 在一个任务空间中复用页面，持久化真实spaceId和页面标签；不要硬编码本轮编号。已结束或属于用户的空间按宿主规则处理，不能擅自重新认领。
- 使用当前快照定位、页面级输入和键盘能力，不抢系统键鼠或激活应用窗口。
- 等可观察的业务状态，不依赖固定睡眠或仅等`商品详情`标题。商品详情应包含所选商品名、实际数字价格和规则；账户和资格信息另外确认。
- 登录或验证码由用户填写时，交接现有页并结束该轮浏览器动作，等用户明确确认后再接回。
- 接回登录/验证码页时，只读必要的页面文本和阶段，不采集密码、验证码输入值或会话凭据。普通商品和订单证据脱敏手机号后保存在任务目录。
- 前一步可能提交过兑换时，恢复只读查订单。即使本地记录没写上“已提交”，当前成功页或订单也优先于旧断点。

## 证据强度

目录/详情可见 → 真实结算可见 → 提交或支付结果 → 扣分核对 → 订单完成 → 运营商/第三方权益明细或回执。

后面的证据没有取得时，不用前面的证据替代。分别报告平台完成和独立权益核验。
